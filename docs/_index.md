# Directory structure

```text
gonfig/                           # repository root
├── AGENTS.md                     # agent instructions
├── README.md                     # project frontpage
├── gonfig.go                     # Gonfig container and main business logic
├── provider.go                   # Provider interface
├── provider/...                  # provider implementations, each module is a separate package
├── example/...                   # examples module (not published)
├── docs/                         # design documentation
│   ├── _index.md                 # documentation entry point
│   ├── design.md                 # design idea, domain terms, entities
│   ├── code.md                   # code conventions most part for the LLM
│   ├── directory-structure.md    # repository layout
│   ├── roadmap.md                # planned work
│   └── output/...                # Snapshot documents generated by LLM 
├── .opencode/                    # OpenCode configuration
│   ├── agents/...                # 
│   ├── commands/...              #
│   └── skills/...                # project skills (one directory per skill)
└── opencode.jsonc                # OpenCode config (skill permissions, commands)
```
<llm-tip> file items which were ignored intentionally and shouldn't be specified in directory tree 
`.git/`, `.gitignore`, `.idea/`, `.work/`, `go.mod`, `go.work`, `gonfig_test.go`, 
`gonfig_util.go`, `/...` - wildcard to stop adding the subitems. </llm-tip>

## docs/output
Generated documents which are actual at a concrete project state, consider them like an audit snapshot,
technical debt, so they can be replaced at once.
html should be used if another format is not specified.
