# Directory structure

```text
gonfig/                           # repository root
├── AGENTS.md                     # agent instructions
├── README.md                     # project frontpage
├── gonfig.go                     # Gonfig container and main business logic
├── provider.go                   # Provider interface
├── provider/...                  # provider implementations, each module is a separate package
├── example/...                   # examples module (not published)
├── docs/                         # design documentation
│   ├── _index.md                 # documentation entry point
│   ├── design.md                 # design idea, domain terms, entities
│   ├── code.md                   # code conventions, mostly for the LLM
│   ├── roadmap.md                # planned work
│   └── output/...                # Snapshot documents generated by LLM
├── .opencode/                    # OpenCode configuration
│   ├── agents/...                #
│   ├── commands/...              #
│   └── skills/...                # project skills (one directory per skill)
└── opencode.jsonc                # OpenCode config (skill permissions, commands)
```
<llm-tip> File items that were intentionally ignored and should not be specified in the directory tree:
`.git/`, `.gitignore`, `.idea/`, `.work/`, `go.mod`, `go.work`, `gonfig_test.go`,
`gonfig_util.go`, `/...` — wildcard to stop adding the sub-items. </llm-tip>

## docs/output
Generated documents that are current at a specific project state: treat them as an audit snapshot and
technical debt, so they can be replaced at once.
HTML should be used if another format is not specified.


# Documents and read order
- [design.md](design.md) — main document that describes the idea: domain terms, Gonfig contracts, Provider interface

- [roadmap.md](roadmap.md) — planned work

- [code.md](code.md) — code conventions and the method that specifies several aspects of code generation by the LLM

- [output/inconsistencies.html](output/inconsistencies.html) — model-vs-code inconsistency registry,
  maintained by `/model-consistency-check`
