Exists — implementation and model consistency

Generated for the Gonfig.Exists addition (Nov 13 2026). Companion to docs/design.md and docs/code.md.

1. What was added

Gonfig.Exists(parts ...string) bool in gonfig.go:77-92:

  • Reuses the same getPath lookup as Get, but returns only the found flag.
  • Exists("a", "b") is true exactly when Get("a", "b") would report ok == true, including a stored nil value.
  • Exists() with no parts mirrors Get(): true when the root map is present (non-nil), false for the zero value.
  • Reads under RLock, so it is safe alongside writers.
  • Performs no deep copy: a bool is a scalar and cannot alias container state.

3. Findings

  • No contradictions. The implementation matches the model.
  • Model updated to include Exists: the class diagram (docs/design.md:31) and the access-methods bullet (docs/design.md:88-89).
  • Deliberate semantic choice: Exists() with no parts reports the presence of the root map — true for an empty but initialized container, false for the zero value — matching Get()’s found flag rather than “has any entries”. This keeps Exists a pure predicate over Get.
  • No README change: the README does not enumerate methods, so it needs no entry.

5. Notes

  • Exists is intentionally copy-free: the copy-contract exists so callers cannot mutate container state through a returned reference. A bool carries no reference, so there is nothing to protect.
  • The method is read-only; it never initializes or mutates the root.
