Inconsistencies

The registry of divergences between the design model (docs/) and the implementation: what the model says, what the code or the other docs do instead, and the prepared change that resolves it. The /model-consistency-check command maintains this document — the reviewer agent prepares the entries, the session that ran the check appends them.

Rules

  • IDs are sequential (IC-001, IC-002, …) and never reused, even after the entry is removed.
  • Resolved entries are removed once the fix or the resolution is agreed.
  • A repeated finding updates the existing open entry instead of adding a duplicate.

[IC-013] "Bound safety" copy claim contradicts Get references and map-level copy depth

  • SeverityMajor
  • Kindcontradiction
  • Statusopen
  • Model saysdocs/model.md:29-30 — "All methods that accepts a key-value collection creates an internal copy. same approach is applied to the outbound methods - every method makes a copy."
  • RealityGet returns live state — gonfig.go:59-60 documents "Get returns live configuration values ... a map-valued key comes back by reference, so do not mutate results", pinned by gonfig_test.go:140 (TestGetWholeConfigReturnsLiveMap) and :161 (TestGetMapValueReturnsReference). Inbound copying is also map-level only: DeepCopyMap copies map[string]any levels and shares every other value (gonfig_util.go:4-19; gonfig_test.go:748 and :761).
  • Prepared changeReword model.md:29-30 to the actual contract — constructors and merges copy map levels (other values shared); Raw returns a map-level copy; Get returns live references. Changing Get to copy would be a breaking API change and is not recommended.
