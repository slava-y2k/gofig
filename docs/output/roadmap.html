1. Summary

The backlog has three feature/decision items, two applied items, and a set of model↔implementation consistency findings:

  • Feature / decision items (3): implement gonfig tag, prepare the provider list, and drop the bool return from Get.
  • Applied (2): IC-015 “deep copy” wording and [Get-copy] — the full deep copy for Get — both done (see §2).

Key insight: the model specifies a full deep-copy contract — Get and Raw both return deep copies, and every accepted or returned item is a deep copy. The code now implements that contract: Get returns a full deep copy, and Raw/DeepCopyMap deep-copy maps, slices, arrays, pointers, and structs. The remaining work is the Get signature decision and the doc-only wording fixes.

2. Applied

IC-015 — the “deep copy” wording was first replaced with “map-level copy” across gonfig.go, docs/design.md, and docs/code.md. The direction then changed to a full deep-copy contract, so that rewording is now superseded: the docs again say “deep copy”, but with an explicit definition (“if a value is a map or another reference type, a new copy is created for it”). No behavior change either way.

[Get-copy] — Get now returns a full deep copy instead of a live reference, so a caller that keeps a result cannot mutate the container’s internal map through it. DeepCopyMap deep-copies maps, slices, arrays, pointers, and structs via reflection; Get returns the deep copy for both the whole map and a path hit; setPath deep-copies any leaf. The live-reference and sharing tests were rewritten as copy tests (TestGetWholeConfigReturnsCopy, TestGetMapValueReturnsCopy, TestGetSliceReturnsCopy, TestGetTypedMapReturnsCopy, plus DeepCopyMap slice/typed-map/pointer/struct cases).
