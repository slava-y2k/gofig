3. Nearest feature work (in order)

Phase A — Decide and apply the Get signature

Backlog item: “In Get method bool return is not required”. The model prose (docs/design.md:77-78) already describes value-only returns (“nil when missing”), while the diagram and code return (any, bool). Decide and make all sides agree.

  • If dropping bool: update gonfig.go:57, getPath, the diagram (docs/design.md:30), gonfig_test.go call sites, and the README quick-start.
  • If keeping bool: reword the model prose to match the diagram instead.

Not trivial — this touches the public API, tests, and examples.

Phase B — Prepare the provider list

Backlog item: “Prepare the provider list for the implementation.” Produce a short ranked list of provider packages (e.g. env, file/json, file/yaml, flags) with their dependencies and a first-implementation target. Then implement the first one following the existing provider/keyvalue pattern (separate module, Read() map[string]any).

Phase C — Implement the gonfig struct tag

Backlog item: “implement gonfig tag”. Map structs to configuration via a struct tag (like envconfig/mapstructure). Largest item; defer until A and B land so the copy-contract and Get semantics are stable.

4. Suggested sequence

  1. Now (trivial): apply §2.1–2.3 doc fixes — zero behavior/test risk.
  2. Next: Phase A — settle the Get signature.
  3. Then: Phase B — provider list + first provider.
  4. Last: Phase C — gonfig tag.
