1. Summary

The backlog has five feature/decision items, one applied doc-fix item, and a set of model↔implementation consistency findings:

  • Feature / decision items (5): implement gonfig tag, prepare the provider list, drop the bool return from Get, make Get return a full deep copy, and test that deep copy.
  • Applied doc fix (1): IC-015 “deep copy” wording — done, then superseded by the deep-copy direction (see §2).
  • Consistency findings: 1 Critical, 4 Major, 8 Minor.
  • Model gaps (2): no method signatures in prose; zero value / errors / helpers undefined.

Key insight: the model now specifies a full deep-copy contract — Get and Raw both return deep copies, and every accepted or returned item is a deep copy. The code still returns live values from Get and map-level copies from Raw/DeepCopyMap (nested map[string]any only; slices and typed maps shared). The nearest work is therefore a small behavior change — implement the full deep copy for Get plus tests — followed by the remaining doc-only wording fixes.

2. Applied

IC-015 — the “deep copy” wording was first replaced with “map-level copy” across gonfig.go, docs/design.md, and docs/code.md. The direction then changed to a full deep-copy contract, so that rewording is now superseded: the docs again say “deep copy”, but with an explicit definition (“if a value is a map or another reference type, a new copy is created for it”). No behavior change either way.

3. Nearest work

3.1 Make Get return a deep copy (behavior change)

Backlog items: [Get-copy] implementation and tests. Today Get returns live state: the whole map when no parts are given, and map values by reference. A caller that keeps the result can mutate the container’s internal map through it. Change Get to return a full deep copy instead.

  • Implement a full deep copy: maps and reference types (slices, typed maps) get new copies. The current DeepCopyMap copies only nested map[string]any levels and shares slices/typed maps, so it is not enough.
  • Update Get’s doc comments and the copy-contract wording in gonfig.go (currently “live values” / “map-level copy”).
  • Rewrite the two tests that pin the live-reference behavior — TestGetWholeConfigReturnsLiveMap and TestGetMapValueReturnsReference — to assert that mutating a Get result does not change the container.

Behavior + API contract change; touches gonfig.go and tests, not just docs.

3.2 Decide the Get signature

Backlog item: “In Get method bool return is not required”. The model prose (docs/design.md) already describes value-only returns (“nil when missing”), while the diagram and code return (any, bool). Decide and make all sides agree.

  • If dropping bool: update gonfig.go, getPath, the diagram, gonfig_test.go call sites, and the README quick-start.
  • If keeping bool: reword the model prose to match the diagram instead.

Not trivial — this touches the public API, tests, and examples.
